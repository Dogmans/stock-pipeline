# 2026-09-09 — Quality scoring and reporting corrections

## Context and scope

A repository review identified incorrect quality scores, reports that counted
nonqualifying stocks as passing, duplicate summary generation, and gaps in offline
pipeline coverage. This change addresses those issues and makes whole-screener
failures visible. FMP remains the existing screening provider; no provider injection
or new provider abstraction was added.

## Changes

- Quality scoring now compares FMP decimal ratios directly with decimal thresholds.
  Previously, converting 1% ROE, profit margin, and operating margin to percentage
  units produced 7 points rather than the intended zero. Display percentages retain
  their existing units, and the strict threshold comparisons remain unchanged.
- Markdown summary counts distinguish scored rows from passing rows. Both Markdown
  and text reports select only rows with `meets_threshold=True`; missing flags within
  that column do not pass. Legacy results without the column remain treated as
  prefiltered results.
- Removed the fallback that displayed nonqualifying stocks when fewer than five
  passed. Display limits apply after filtering; zero shows all passing stocks, and
  negative limits are rejected.
- Replaced two writes to the summary file with one reporting function, using the
  same sorted results and passing criteria as the Markdown report.
- Exceptions escaping a screener are recorded separately from empty successful
  results. Reports identify the failed strategy, retain other successful strategies,
  and the CLI exits with status 1 when a screener fails. This does not recover partial
  rows from inside a failed screener or change provider-level error handling.
- The pipeline regression exposed formatting failures for absent metrics such as
  P/E. Reports now render missing values as placeholders and use the score as a
  summary fallback when no supported metric is available.

## Validation

Added 10 offline regression tests covering threshold boundaries, missing data,
passing counts, display limits, empty results, legacy results, and failure reporting.
The pipeline test exercises the real registry, quality screener, and report writers
with mocked external data. All 10 tests passed.

The dedicated runner uses temporary cache, log, and output storage, disables `.env`
loading, supplies a dummy FMP key, and blocks network requests. The existing virtual
environment launcher could not start, so validation used installed Python 3.12 with
the existing environment's dependencies. Commands are recorded in
[the testing guide](../testing.md#offline-scoring-and-reporting-regressions).

All five changed or added Python files passed syntax parsing, and `git diff --check`
passed. The existing full suite and live API tests were not run.

## Remaining review findings

Cache command inconsistencies, HTTP timeout/retry handling, legacy module cleanup,
and broader test/CI improvements remain separate follow-up work.

## FMP performance follow-up

Investigated throttling and HTTP latency, then corrected the manual cache lookup
and enabled HTTP connection reuse at the user's request. The cache checker uses
DiskCache's own key generator for all seven decorated FMP methods. A shared session
handles central and insider requests and closes at process exit; keeping it outside
provider instances preserves existing memoization keys. Rate limits are unchanged.

All 14 offline regressions passed. A nine-request live check returned HTTP 200 for
every request, confirmed the corrected cache probe, and measured 1.325 seconds of
HTTP time versus 3.62 seconds before the fix. See
[the performance investigation](../fmp_performance.md) for methodology, limits,
and reproduction instructions. Analyst caching and throttle consolidation were
not included in this change.
